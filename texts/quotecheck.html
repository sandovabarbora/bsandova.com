Overwhelmed? Here's the short version
  • It compares a quotation with its source, ignoring case, ligatures, hyphens, accents and quotation marks.
  • It answers FOUND, FOUND*, DRIFT or ABSENT, and can check every quotation in a note.
  • Its accuracy has not been measured on a labelled set.
  • It can only judge a quotation against a source it has been shown.

What it does, and comparable tools

An agent reading the ISACA CISA Review Manual produced this sentence as ISACA's own words: "a security audit does not typically test information security in an organization but just indicates the extent of compliance with standards". The manual does not contain that sentence. quotecheck was written after that fabricated quotation reached a wiki that an agent keeps, which quotes its sources hundreds of times. It answers one question: does this quotation occur in this source?

The clause "indicates the extent of compliance with standards" does occur once, in the other column of a two-column page. The manual is a 304 MB scanned PDF. The likely route, inferred from one case, is pdftotext, a common PDF-to-text converter, whose -layout mode can join two columns line by line into sentences that never existed1. In the author's reading, the sentence survived review because it matched what the brief was looking for: the compliance profession criticising itself. In the wiki's own repository, the checker's earlier form is the script quote.py (private; not verifiable).

General fuzzy matchers already find near-matches of a string in a text. Python's difflib scores how similar two sequences are2. RapidFuzz quickly computes Levenshtein scores (edit distance, the fewest character insertions, deletions or substitutions that turn a string into another), including a partial_ratio for the best-matching substring3. Work on citations in language-model output, such as the ALCE benchmark, asks a different question: does a cited passage support a generated claim? ALCE answers it with a model4.

quotecheck is narrower than either. It asks whether the words in quotation marks are in the source verbatim. It gives a named, ordered answer rather than a score. And it shows the reader only the source's original text, never the normalised form in which the match was found.

Method: folding, an offset map and four answers

Both the source and the phrase are folded to a comparison key. Folding means lower case, ligatures expanded, hyphens and dashes dropped on both sides, whitespace dropped, accents stripped and quotation marks removed. Each rule exists because of a genuine quotation that an earlier check called fabricated.

The first check was grep. It reported three fabrications that were all real. One began a sentence, and the check was case-sensitive. One was hyphenated across a PDF line break as vibra- tion. One spanned a line break. Ligatures (tradeoﬀ stored as one glyph), accents (Niccolo typed for Niccolò) and nested quotation marks followed over the next days.

Hyphens are dropped on both sides for words such as cross-validation broken at their own hyphen at the end of a line. Without that, such a word could not be matched both when it is typed with the hyphen and when it is typed without it. The fold keeps a map from every folded character back to its offset in the original. So the match is found on the key, and the context is printed from the source5.

The four answers are tried in order of strictness. FOUND gives the count and the surrounding text.

FOUND* means the phrase occurs as two adjacent halves. Each is at least twelve folded characters long, with at most twelve folded characters between them. That is what a page number or running head looks like when a scan drops it into a sentence. A running head is the book or chapter title printed at the top of each page. Digits are not folded away, because a changed year or count is a changed quotation. A splice, two fragments from different parts of a book joined into a sentence, fails because the halves are not adjacent.

The gap may hold any twelve folded characters, not only digits or a running head. So a quotation that silently drops a short word from the middle of a sentence, such as not or never, is also reported FOUND*. The context line shows the dropped text, so a FOUND* should be read before it is accepted. Only one split is tried: the longest opening of the phrase that occurs anywhere, at its first occurrence.

DRIFT is reported when the phrase does not occur but a window of the source comes close. The window is as long as the phrase and aligned on their longest common run of at least eight folded characters. Its similarity must be at least 0.80, measured as difflib.SequenceMatcher.ratio(): twice the matched characters over the total characters of the two folded strings. The tool then prints what the source says, and drift counts as not found. Anything else is ABSENT.

In batch mode the tool reads a Markdown note and checks each one of the quotations it extracts. It takes every blockquote line of six or more words, checked line by line. It also takes every run of six or more words (at least twenty characters) inside double quotation marks, straight or curly. Quotations in single quotation marks are not extracted, and a blockquote of several lines is never checked as one passage5.

Worked example: four books

$ quotecheck East-of-Eden/source.txt "For if Thou mayest—it is also true that Thou mayest not"
FOUND   1x  For if Thou mayest—it is also true that Thou mayest not
        …That throws it right back on a man. For if ‘Thou mayest’—it is also true that ‘Thou mayest not.’ Don’t you see?…

$ quotecheck mathsapology-hardy/source.txt "If a man has any genuine talent he should be ready to make almost any sacrifice"
FOUND*   If a man has any genuine talent he should be ready to make almost any …
        …If a man has any genuine talent he 4 should be ready to make almost any sacrifice in order to cultivate it to the full…

$ quotecheck CISA-Review-Manual/source.txt "a security audit does not typically test information security in an organization but just indicates the extent of compliance with standards"
ABSENT   a security audit does not typically test information security in an or…

$ quotecheck Mans-Search-for-Meaning/source.txt "Between stimulus and response there is a space"
ABSENT   Between stimulus and response there is a space

These four runs were made against the extracted full text of the four books. They are reproduced here with the context lines shortened, since the tool prints about sixty folded characters of source on each side of the match6.

Steinbeck's sentence had been transcribed without its inner quotation marks, and it is found. Hardy's is found in two halves around a page number, 4, that the scan most likely put inside the sentence. The ISACA sentence is absent. So is the sentence most often attributed to Viktor Frankl, "Between stimulus and response there is a space. In that space is our power to choose our response", in the text of the Beacon Press edition of Man's Search for Meaning that was checked. Quote Investigator could not find it in Frankl's works either. It traces the sentence's spread to Stephen R. Covey, who said he had read it in a book he could not identify7.

Tests and measured error

The package has 20 tests. They run on Python 3.10 to 3.13 in GitHub Actions and passed locally on 29 September 2026. The fixture is a short invented source with one instance of each false-alarm class. The tests require each genuine quotation to be found, a reworded sentence to be reported as drift, a fabrication to be absent, and a splice of two real fragments not to pass as FOUND*. The rest cover batch extraction and the command line5.

No error rate has been measured on a labelled set of quotations, so the tool's accuracy rests on these tests and the runs above. The larger checks in the wiki are part of its private log and cannot be verified outside it1.

According to that log, after the ISACA fabrication all 292 quoted passages on the 15 CISA pages were checked by machine against the source on 27 August 2026, before this tool existed. The same log says about seven more passages had no matching run of words, though their substance could be traced in the source. The fabricated quotation was removed, and the removal was recorded on its page. Every CISA page now carries a note: its terminology and structure are reliable, and its verbatim sentences are not.

The log also records that on 28 August 2026 two agents, asked to re-check their own finished pages, found sixteen defects between them: one misquotation in the first person, one substituted conjunction and fourteen splices, two real fragments joined into a sentence the book does not contain. A splice passes any check made on a quotation before it is written, since both halves are in the source. That is why batch mode checks the finished page.

Limits

The tool needs the source as text, and it is only as good as the extraction. A two-column scan still produces sentences that read well and never existed. The tool will find them, because they are in the text it was given. The drift threshold of 0.80 and the twelve-character gap were set by hand on these cases and have not been tuned or validated on other material.

FOUND* accepts any twelve folded characters inside a sentence, so a quotation that omits a short word such as not passes as found. It also tries only the longest matching opening at its first occurrence. A genuine interrupted quotation whose opening words recur earlier in the book can therefore be reported as drift or absent. The tests cover a splice whose halves are far apart, not an omitted negation.

Dropping whitespace also drops word boundaries: "the rapist" is FOUND in a source that says therapist, and the reverse. The tool does not judge whether a paraphrase is fair, only whether quotation marks were earned. And it says nothing about a quotation from a source it has not been shown.

Install and reproduce

The package installs with pip install quotecheck and has no required dependencies. It reads plain text, Markdown, HTML, EPUB and PDF. PDF goes through pdftotext when it is installed, or through pypdf after pip install "quotecheck[pdf]". A single check is quotecheck source.txt "phrase", and quotecheck source.txt --batch note.md checks a whole note.

The four runs above cannot be reproduced from the repository, because the books are copyrighted and their text is not redistributed. The test fixtures in tests/ are the reproducible substitute. Clone the repository and run uv run pytest, and every rule and answer described here is exercised5.
