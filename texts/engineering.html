1 · Cloud architecture as code

The platform serves several job portals and HR products across AWS and GCP. The seam between the clouds is keyless: AWS Step Functions authenticate to BigQuery through Workload Identity Federation, so there is no service-account key to rotate, leak or forget. The whole stack is infrastructure as code, AWS CDK in Python and Terraform, across production and development accounts: ECS/Fargate services, Lambda, Step Functions, ECR, ALB routing, S3, IAM, Secrets Manager, SSM1. Nothing on the platform exists only in a console. If it is not in the repository, it is not there.

Smaller pieces that follow from the same rule. A hand-built Windows bastion, needed to reach a partner MySQL behind an IP allowlist, was captured as IaC: SSM Session Manager only, no inbound security-group rules, no exposed RDP, IMDSv2 required, encrypted root volume. Cross-account backup on RDS and EFS was standardised so backups survive the loss of the source AWS account, arguing against the documented S3 path in favour of versioning and replication. And the dependency chain got the same treatment: shared libraries live in a private AWS CodeArtifact registry as the single source of truth, which is also where the broken wheel metadata that had leaked local paths into published packages was found and fixed.

2 · Deploying without blocking everyone

Two design decisions I would make again. Scoped deployments: the deploy job derives which stacks a change touched from the live CDK construct tree rather than from a hand-maintained lookup table. It is rename-proof, and one broken app no longer blocks the deploy of every other app, which used to be the normal Tuesday. ECR + App stack pairs: eight analytics apps, each one monolithic stack, refactored into an image stack and a runtime stack with shared constructs. The image tag is handed across through SSM Parameter Store instead of CloudFormation exports, so container and runtime configuration deploy independently and an export lock never holds a rollout hostage1.

Deploys run from GitHub Actions. The same actions also run the audits described below, on a schedule, so "who checked this" always has the answer "the workflow, at 03:00, here is the log".

3 · Observability as code

A dashboard clicked together in the console has three problems: it drifts, it disappears when the account is rebuilt, and nobody reviews it. So dashboards and alarms are CDK constructs that live next to the service they watch, in the same pull request. A new ECS service gets its CloudWatch dashboard and its alarms by construction, and a deleted service takes them with it. The alarms are on service-level objectives, latency and 4XX/5XX error rates, not on CPU, because a customer never complained about CPU. Breaches go to Slack, where the on-call engineer is, rather than to an email nobody reads1.

Monitoring does not stop at the infrastructure layer, and most of what breaks in a data platform is not the infrastructure. The table lists what is watched where, and what happens when it trips. Everything in it is code and everything in it has a defined action; a signal without an action is a screensaver.

4 · Security and access

Access is least privilege by construction, in Terraform: per-project groups with read-only access everywhere and write access only in a personal sandbox, replacing the blanket "full analyst" role a new joiner used to get on day one. Partner databases moved from static credentials to RDS IAM authentication through assume-role chains with short-lived tokens, so there is no password to rotate and nothing to paste into a chat. Between the clouds, Workload Identity Federation does the same job at the platform level1.

The same discipline applies to AI agents, where it is newer and rarer. An autonomous agent is scoped so it cannot reach resources outside its remit. A service-account-backed assistant turned out to be a confused deputy, a user could make the assistant's credentials do what the user's own could not, and the fix was per-domain protection domains enforced at BigQuery IAM, not a line in the prompt. The assistant's MCP surface, forty exposed tools of which eighteen could write, was cut to a fifteen-tool read-only allowlist, with a project-scoping wrapper that rejects out-of-scope queries before they reach the warehouse. A prompt is a suggestion. IAM is a wall.

The habit predates the job. I studied data science and cybersecurity at VŠE (thesis in pattern engineering for cybersecurity, nominated for the national IT SPY award in 2025), spent a year in fraud and forensic analytics at EY, and when an independent security review of FilmRunner came back I acted on all of it: an IS_DEV blocklist that failed open on a blank environment variable became an explicit allowlist, and SSO auto-provisioning was gated on a server-side SAML claim rather than a client assertion1.

5 · Data platform: dbt and Dagster

dbt modernisation: Python models on Dataproc/Spark for latency-sensitive transformations such as NLP and language detection, a BigQuery materialisation and cost strategy, incremental models with unique keys over self-referential deltas. Dagster orchestrates extracts containerised as Docker images across many portal sources; multi-organisation CRM extraction was made resilient so that one organisation's missing entity skips instead of aborting the run for everyone else1.

The choice between SQL and Python models is a cost choice, not a taste choice. A language-detection pass over job adverts is a Python model on Spark because BigQuery would do it slowly and expensively; a daily salary aggregate is SQL because the warehouse does aggregates better than anything I could write. Materialisation follows the same logic: incremental where the delta is identifiable by a key, table where it is not, view where nobody reads it often enough to pay for storage.

6 · Proving that nothing changed

The cutover I am proudest of is boring on purpose. A legacy salary-recompute pipeline moved from a standalone extractor to an incremental dbt-python model. Before a single downstream consumer was repointed, the new model was proven byte-identical to the old one across five years of history: zero mismatches across twenty columns. Shipped with backups, freshness tests and a git-revert rollback path. Same habit on a production GA4 event-stream backfill: validated by full-row fingerprint, 62 of 62 days identical to the pre-backfill snapshot, dev ≡ prod, and the one-off operation kept out of the production codebase1.

The method is simple and I use it everywhere: compute both sides, key them, diff every column with a tolerance for floats, hash each day's rows and compare the hashes, and only then touch the consumers. On this site the hockey atlas's graph ingest is preceded by the same idea in miniature: a read-only merge check computes the ids it would write and counts collisions before it mutates anything, which caught a bug that would have created about 570 phantom players3. The number that matters in a migration is the one that says nothing changed.

7 · An LLM assistant, measured before it was trusted

The goal: non-technical staff self-serve BI questions and analysts stop being the bottleneck. The build: a LangGraph agent behind FastAPI on the Anthropic API, with MCP connectors to BigQuery, OpenMetadata and Metabase. The first decision was to replace a ~4 500-line bespoke NL→SQL service (Vanna, ChromaDB, a custom pipeline) with a ~400-line agent whose domain knowledge lives in the data catalogue instead of the codebase, chosen on maintenance cost per line, at parity on the golden question sets1.

Then the trust layer, which is what Quaesitor is about: every figure the assistant returns is cross-checked against certified BI dashboards, lookup is catalogue-first, and protocol compliance is an explicit evaluation metric, not a hope. Then hardening after measuring: the tool allowlist and scoping wrapper above, and hard caps, added after a single unbounded question consumed 4.07 million input tokens and $21 without failing. The eval harness over verified golden sets found a malformed output schema in a third-party MCP server that was silently discarding results, non-deterministically; without the harness that would have been "the assistant is sometimes wrong". The first business POC ran with the stakeholders in the room: their real questions became date-fixed golden cases, ambiguous definitions (category semantics, tier models, credit balances) were driven to authoritative answers and written into the OpenMetadata glossary, so the agent inherits them instead of re-deriving them per question.

8 · Developer experience

A multi-app repository migrated from Poetry to uv, lockfile resolution from about thirty seconds to under one per app. Dependabot alerts cut from 792 to 332 through dependency and Python-pin cleanup across fifteen library manifests and eight apps. The internal documentation site rebuilt on Zensical with the Diátaxis structure, tutorials apart from reference apart from explanation, so an analyst can get a first app running without reading CDK internals12. Onboarding is an access-design problem as much as a documentation problem; the Terraform groups in section 4 are what makes day one safe, and the docs are what makes it short.

9 · How I work

Infrastructure as code, always. Least privilege as the default, for people and for agents. Read-only verification before mutating shared state. Parity and fingerprint validation before any cutover. Decisions written down as ADRs with the rejected options kept. Evaluation harnesses and golden sets before anyone calls a model "good". Cost guardrails sized from measured runs, not from hope. An honest limitations section in every report, including the ones on this site. Documentation in the Diátaxis shape. And no figure typed by hand anywhere a script could have produced it.

11 · What runs this site

The same habits, in public, where they can be checked. The model release watch runs the Quaesitor harness (524 tests) monthly from a launchd job with the operator's own tool configuration stripped, indexes every report with its fingerprints and cost, and pushes a data file the page renders from. The surf forecast verification is a GitHub Actions cron with append-only JSON, idempotent collectors, data-quality counts that found a model dropout on day one, sample-size gates, block-bootstrap intervals and a six-test suite that has to pass before a number is shown. The hockey atlas's graph ingest has the read-only merge check from section 6. The football atlas was built spec → plan → task agents → reviews, with 163 tests and 23 dated rulings. And Quaesitor's site refused to build when a run stopped supporting a sentence. That rule is on every page here: no figure is typed3. Whether each of these jobs actually ran, how fresh its data is against the cadence it promised and what it cost is on the status page, read live from the same files and from GitHub.
