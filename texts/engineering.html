Cloud architecture as code

The platform serves several job portals and HR products across AWS and GCP. The seam between the clouds is keyless: AWS Step Functions authenticate to BigQuery through Workload Identity Federation, so there is no service-account key to rotate, leak or forget. The whole stack is infrastructure as code, AWS CDK in Python and Terraform, across production and development accounts: ECS/Fargate services, Lambda, Step Functions, ECR, ALB routing, S3, IAM, Secrets Manager, SSM1.

Two design decisions I would make again. Scoped deployments: the deploy job derives which stacks a change touched from the live CDK construct tree rather than from a hand-maintained lookup table, so it is rename-proof and one broken app no longer blocks the deploy of every other app. ECR + App stack pairs: eight analytics apps, each one monolithic stack, refactored into an image stack and a runtime stack with shared constructs, the image tag handed across through SSM Parameter Store instead of CloudFormation exports, so container and runtime configuration deploy independently. Smaller pieces, too: a hand-built Windows bastion captured as IaC with SSM Session Manager only (no inbound rules, no exposed RDP, IMDSv2, encrypted root) to reach a partner MySQL behind an IP allowlist; cross-account backup on RDS and EFS so backups survive the loss of the source account, arguing against the documented S3 path in favour of versioning and replication.

Observability, reliability, security

Dashboards and alarms are CDK code: SLOs on latency and 4XX/5XX rates, wired to Slack. ECR vulnerability scanning and cross-account security audit workflows run on schedule. Access is least privilege by construction, in Terraform: per-project groups with read everywhere and write only in a personal sandbox, replacing the blanket "full analyst" role a new joiner used to get. Partner databases moved from static credentials to RDS IAM authentication through assume-role chains and short-lived tokens1.

The same discipline applies to AI agents. An autonomous agent is scoped so it cannot reach resources outside its remit; a service-account-backed assistant turned out to be a confused deputy, and the fix was per-domain protection enforced at BigQuery IAM, not in the prompt. A prompt is a suggestion. IAM is a wall.

Data platform: dbt, Dagster, and proving a cutover

dbt modernisation: Python models on Dataproc/Spark for latency-sensitive transformations such as NLP and language detection, a BigQuery materialisation and cost strategy, incremental models with unique keys over self-referential deltas. Dagster orchestrates extracts containerised as Docker images across many portal sources; multi-organisation CRM extraction was made resilient so that one organisation's missing entity skips instead of aborting the run1.

The cutover I am proudest of is boring on purpose. A legacy salary-recompute pipeline moved from a standalone extractor to an incremental dbt-python model. Before a single downstream consumer was repointed, the new model was proven byte-identical to the old one across five years of history: zero mismatches across twenty columns. Shipped with backups, freshness tests and a git-revert rollback path. Same habit on a production GA4 event-stream backfill: validated by full-row fingerprint, 62 of 62 days identical to the pre-backfill snapshot, dev ≡ prod, and the one-off operation kept out of the production codebase. The number that matters in a migration is the one that says nothing changed.

An LLM assistant, measured before it was trusted

The goal: non-technical staff self-serve BI questions and analysts stop being the bottleneck. The build: a LangGraph agent behind FastAPI on the Anthropic API, with MCP connectors to BigQuery, OpenMetadata and Metabase. The first decision was to replace a ~4 500-line bespoke NL→SQL service (Vanna, ChromaDB, a custom pipeline) with a ~400-line agent whose domain knowledge lives in the data catalogue instead of the codebase, chosen on maintenance cost per line, at parity on the golden question sets1.

Then the trust layer, which is the part Quaesitor is about: every figure the assistant returns is cross-checked against certified BI dashboards, lookup is catalogue-first, and protocol compliance is an explicit evaluation metric, not a hope. Then hardening after measuring: 40 exposed MCP tools, 18 of them write-capable, cut to a 15-tool read-only allowlist; a project-scoping wrapper that rejects out-of-scope queries before they reach BigQuery; and hard caps, added after a single unbounded question consumed 4.07 million input tokens and $21 without failing. Pseudonymous per-run tracing (fourteen fields, a salted user hash and team, never names, never tool outputs) and an eval harness over verified golden sets found a malformed output schema in a third-party MCP server that was silently discarding results, non-deterministically. The first business POC ran with the stakeholders in the room: their real questions became date-fixed golden cases, ambiguous definitions (category semantics, tier models, credit balances) were driven to authoritative answers and written into the OpenMetadata glossary, so the agent inherits them instead of re-deriving them per question.

Developer experience

A multi-app repository migrated from Poetry to uv, lockfile resolution from about thirty seconds to under one per app; shared libraries moved to a private AWS CodeArtifact registry as the single source of truth, which also fixed wheel metadata that had leaked local paths into published packages. Dependabot alerts cut from 792 to 332 across fifteen library manifests and eight apps. The internal documentation site rebuilt on Zensical with the Diátaxis structure, so an analyst can get a first app running without reading CDK internals12.

What runs this site

The same habits, in public, where they can be checked. The model release watch runs the Quaesitor harness (524 tests) monthly from a launchd job with the operator's own tool configuration stripped, indexes every report with its fingerprints and cost, and pushes a data file the page renders from. The surf forecast verification is a GitHub Actions cron with append-only JSON, idempotent collectors, data-quality counts that found a model dropout on day one, sample-size gates, block-bootstrap intervals and a six-test suite that has to pass before a number is shown. The hockey atlas's graph ingest is preceded by a read-only merge check that computes the ids it would write and counts collisions first, which caught a bug that would have created about 570 phantom players. The football atlas was built spec → plan → task agents → reviews, with 163 tests and 23 dated rulings. And Quaesitor's site refused to build when a run stopped supporting a sentence. That rule is on every page here: no figure is typed3.
