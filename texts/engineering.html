1 · Cloud architecture as code

The platform serves several job portals and HR products across AWS and GCP. No stored key connects the two clouds: AWS Step Functions authenticate to BigQuery through Workload Identity Federation, so there is no service-account key that could leak or go unrotated. The whole stack is infrastructure as code, AWS CDK in Python and Terraform, across production and development accounts, covering ECS/Fargate services, Lambda, Step Functions, ECR, ALB routing, S3, IAM, Secrets Manager and SSM1. Nothing on the platform exists only in a console; the repository is the inventory.

The same rule covers the smaller pieces. A hand-built Windows bastion, needed to reach a partner MySQL behind an IP allowlist, was captured as IaC with SSM Session Manager as the only way in, no inbound security-group rules, no exposed RDP, IMDSv2 required and an encrypted root volume. Cross-account backup on RDS and EFS was standardised so that backups survive the loss of the source AWS account; I argued against the documented S3 path in favour of versioning and replication. The dependency chain was treated the same way. Shared libraries live in a private AWS CodeArtifact registry as the single source of truth, and that registry is also where broken wheel metadata, which had leaked local paths into published packages, was found and fixed.

2 · Scoped deployments and split app stacks

Two design decisions in the deploy path are ones I would make again. The first is scoped deployments. The deploy job derives which stacks a change touched from the live CDK construct tree rather than from a hand-maintained lookup table, which survives renames and means one broken app no longer blocks the deploy of every other app, as it used to on a normal Tuesday. The second is the ECR + App stack pair. Eight analytics apps, each of them one monolithic stack, were refactored into an image stack and a runtime stack with shared constructs. The image tag is handed across through SSM Parameter Store instead of CloudFormation exports, so container and runtime configuration deploy independently and an export lock can no longer hold a rollout hostage1.

Deploys run from GitHub Actions, and the same actions run the audits described below on a schedule, so when someone asks who checked something, the answer is always "the workflow, at 03:00, here is the log".

3 · Observability as code

A dashboard clicked together in the console drifts, disappears when the account is rebuilt and is never reviewed. Dashboards and alarms are therefore CDK constructs that live next to the service they watch and change in the same pull request. A new ECS service gets its CloudWatch dashboard and its alarms by construction, and a deleted service takes them with it. The alarms are set on service-level objectives, latency and 4XX/5XX error rates, rather than on CPU, since no customer has ever complained about CPU. Breaches go to Slack, where the on-call engineer is, rather than to an email nobody reads1.

Most of what breaks in a data platform is not the infrastructure, so monitoring continues above that layer. The table lists what is watched where and what happens when a signal trips. Every row is code and every row has a defined action.

4 · Security and access

Access is least privilege by construction, in Terraform: per-project groups with read-only access everywhere and write access only in a personal sandbox, replacing the blanket "full analyst" role a new joiner used to get on day one. Partner databases moved from static credentials to RDS IAM authentication through assume-role chains with short-lived tokens, so there is no password to rotate and nothing to paste into a chat. Between the clouds, Workload Identity Federation does the same job at the platform level1.

The same discipline applies to AI agents, where it is newer and rarer. An autonomous agent is scoped so that it cannot reach resources outside its remit. A service-account-backed assistant turned out to be a confused deputy, since a user could make the assistant's credentials do what the user's own could not; the fix was per-domain protection domains enforced at BigQuery IAM rather than a line in the prompt. The assistant's MCP surface, forty exposed tools of which eighteen could write, was cut to a fifteen-tool read-only allowlist, with a project-scoping wrapper that rejects out-of-scope queries before they reach the warehouse. A prompt is a suggestion. IAM is a wall.

I brought the habit to the job from studying data science and cybersecurity at VŠE (thesis in pattern engineering for cybersecurity, nominated for the national IT SPY award in 2025) and from a year in fraud and forensic analytics at EY. When an independent security review of FilmRunner came back I acted on all of it: an IS_DEV blocklist that failed open on a blank environment variable became an explicit allowlist, and SSO auto-provisioning was gated on a server-side SAML claim rather than a client assertion1.

5 · Data platform: dbt and Dagster

The dbt modernisation brought Python models on Dataproc/Spark for latency-sensitive transformations such as NLP and language detection, a BigQuery materialisation and cost strategy, and incremental models with unique keys over self-referential deltas. Dagster orchestrates extracts, containerised as Docker images, across many portal sources. Multi-organisation CRM extraction was made resilient, so that when one organisation is missing an entity, that organisation is skipped instead of the run aborting for everyone else1.

Whether a model is written in SQL or in Python is decided by cost rather than by taste. A language-detection pass over job adverts is a Python model on Spark because BigQuery would do it slowly and expensively; a daily salary aggregate is SQL because the warehouse does aggregates better than anything I could write. Materialisation follows the same logic: incremental where the delta is identifiable by a key, table where it is not, view where nobody reads it often enough to pay for storage.

6 · Parity proofs before a cutover

The cutover I am proudest of was uneventful by design. A legacy salary-recompute pipeline moved from a standalone extractor to an incremental dbt-python model, and before a single downstream consumer was repointed, the new model was proven byte-identical to the old one across five years of history, with zero mismatches across twenty columns. It shipped with backups, freshness tests and a git-revert rollback path. A production GA4 event-stream backfill was handled with the same habit: it was validated by full-row fingerprint, with 62 of 62 days identical to the pre-backfill snapshot and dev ≡ prod, and the one-off operation was kept out of the production codebase1.

In a migration the number that matters is the one showing that nothing changed, and I compute it the same way everywhere. Both sides are computed and keyed, every column is diffed with a tolerance for floats, each day's rows are hashed and the hashes compared, and only after that are the consumers touched. On this site the hockey atlas's graph ingest is preceded by the same idea in miniature: a read-only merge check computes the ids it would write and counts collisions before it mutates anything, and it caught a bug that would have created about 570 phantom players3.

7 · An LLM assistant, measured before it was trusted

The long version of this section, with the architecture, the protocol and the lessons, is AI over data, measured.

The assistant is there so that non-technical staff can answer BI questions themselves and analysts stop being the bottleneck. It is a LangGraph agent behind FastAPI on the Anthropic API, with MCP connectors to BigQuery, OpenMetadata and Metabase. The first decision was to replace a ~4 500-line bespoke NL→SQL service (Vanna, ChromaDB, a custom pipeline) with a ~400-line agent whose domain knowledge lives in the data catalogue instead of the codebase. It was chosen on maintenance cost per line and runs at parity on the golden question sets1.

The trust layer on top of it, which is what Quaesitor is about, cross-checks every figure the assistant returns against certified BI dashboards; lookup is catalogue-first, and protocol compliance is an explicit evaluation metric rather than a hope. Hardening followed the measurements: the tool allowlist and scoping wrapper described above, and hard caps added after a single unbounded question consumed 4.07 million input tokens and $21 without failing. The eval harness over verified golden sets found a malformed output schema in a third-party MCP server that was silently and non-deterministically discarding results, which without the harness would have been filed as "the assistant is sometimes wrong". The first business POC ran with the stakeholders in the room. Their real questions became date-fixed golden cases, and ambiguous definitions (category semantics, tier models, credit balances) were driven to authoritative answers and written into the OpenMetadata glossary, so the agent inherits them instead of re-deriving them per question.

8 · Developer experience

A multi-app repository was migrated from Poetry to uv, which took lockfile resolution from about thirty seconds to under one per app. Dependabot alerts were cut from 792 to 332 through dependency and Python-pin cleanup across fifteen library manifests and eight apps. The internal documentation site was rebuilt on Zensical with the Diátaxis structure, keeping tutorials, reference and explanation apart, so that an analyst can get a first app running without reading CDK internals12. Onboarding is an access-design problem as much as a documentation problem: the Terraform groups in section 4 make day one safe, and the docs make it short.

9 · How I work

I keep infrastructure as code, always, and least privilege as the default for people and for agents. Shared state is verified read-only before it is mutated, and no cutover happens without parity and fingerprint validation. Decisions are written down as ADRs that keep the rejected options, and nobody calls a model "good" before there is an evaluation harness and a golden set. Cost guardrails are sized from measured runs rather than from hope. Every report carries an honest limitations section, including the ones on this site. Documentation follows the Diátaxis shape, and no figure is typed by hand anywhere a script could have produced it.

11 · What runs this site

The same habits run this site in public, where they can be checked. The model release watch runs the Quaesitor harness (524 tests) monthly from a launchd job with the operator's own tool configuration stripped, indexes every report with its fingerprints and cost, and pushes a data file the page renders from. The surf forecast verification is a GitHub Actions cron with append-only JSON, idempotent collectors, data-quality counts that found a model dropout on day one, sample-size gates, block-bootstrap intervals and a six-test suite that has to pass before a number is shown. The hockey atlas's graph ingest has the read-only merge check from section 6. The football atlas was built spec → plan → task agents → reviews, with 317 tests and dated ledgers. Quaesitor's site refused to build when a run stopped supporting a sentence, and the same rule holds on every page here3.

Whether each of these jobs ran, how fresh its data is against the cadence it promised and what it cost is shown on the status page, read live from the same files and from GitHub. What the site itself changed, commit by commit, is on the changelog, generated from git log at every deploy. The domain is code as well: the Cloudflare zone (DNS, the www-to-apex redirect, security headers on every response, HTTPS only, TLS 1.2 or better) is Terraform in infra/, adopted by declarative imports so nothing was recreated, and the Worker that serves the site deploys from the repository on every push.
