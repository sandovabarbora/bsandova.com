What it does, and comparable tools

The Ask page answers questions about this site from its texts and data files. It started as about two hundred lines in a Cloudflare Worker, with four rules written into the prompt and two of them checked after the fact. sitewitness is the Python package that replaced it on 21 and 22 September 2026. It indexes a site's texts into passages and its JSON files into schemas, gives a model five tools (search, read_data, describe_source, quote and list_sources, which lists the site's data files), runs the agent loop (the model calling tools turn by turn until it answers) behind a small server, and applies five rules to every answer before it is returned. An answer that breaks a rule is replaced by a fixed refusal, and the trace, the per-answer log of tool calls, tokens and rule results, records which rule fired1.

Output checks of this kind are common. Guardrails AI wraps model calls in input and output guards built from validators, many of them published on its hub2. NeMo Guardrails defines input, dialog, retrieval, execution and output rails, several of which are themselves model calls, such as self-checking for hallucination3. RAGAS measures faithfulness offline by having a model split an answer into claims and checking each claim against the retrieved context4. sitewitness is cruder. Its rules are plain functions over the answer text and the trace of tool calls, with no second model, so they are deterministic, cheap and testable, and they check only what can be read off the text, such as whether a number appears when no data were read.

Method: five rules and the run-time limits

An answer with no tool call is refused, and so is an answer that contains a digit when the conversation holds no result from read_data, search or describe_source. Fenced code, a line starting with def, import or from, or an HTML tag is refused. A passage of forty characters or more inside quotation marks is refused unless its words occur in a tool result of the conversation or the quote tool returned any phrase as found in that conversation; one verified quotation therefore exempts every other quotation in the same answer. A Sources: line naming a file or page the site does not have is refused as well. The first violated rule wins, the refusal replaces the answer, and the original answer is kept in the trace. A refusal is never itself refused, and the rules can be switched off only in the configuration file1.

Around the rules sit the limits a public endpoint needs: a daily budget and a per-address rate in a pluggable store, a cap on model turns that may call tools (eight on this site, checked before each batch of calls; one turn can issue several calls, and saved answers used up to 17), caps on output tokens and wall time, and a final turn without tools when a cap is reached, so that an answer is never empty. Cost is computed from configured prices, and the trace records every tool call with its input, size and time. The package uses no agent framework; the model client is an interface with one method1.

Worked example: one traced answer

The saved evaluation of 22 September 2026 contains one answer that a rule replaced. The record, shortened, reads as follows5.

q         Which September watch runs have an unverified model attribution?
expect    unverified
tools     describe_source, read_data × 8
original  Only one September run has an unverified model attribution: the "opus" alias run on the
          abstention pack dated 2026-09-14 (…). Its model field is recorded as "unverified" because …
enforced  quotes_need_verification
answer    I can't answer that from this site. This assistant answers only from the site's data files …
ok        false

The original answer contains the expected word. The quotation rule fired because its pattern takes any run of forty or more characters between two quotation marks as a quotation, and here it spanned the text between two short quoted words, "opus" and "unverified", marked above. The refusal was therefore a false one, and the run's only miss.

Tests and the evaluation runs

The package has 47 tests, run on Python 3.10 to 3.13 in GitHub Actions and passing locally on 29 September 2026; the model client is replaced by a stub, so no test calls the network. The golden set is thirty questions about the site, each with an expected substring or an expected refusal. 18 are labelled as data questions whose answer must come from read_data (13 expect a number, 5 a name or status read from a file), 7 as text questions, 1 as a quotation and 4 should be declined. An answer counts as correct if it contains the expected string anywhere after case, spaces and thousands separators are normalised, unless it also contains the refusal phrase; a decline counts if the refusal phrase appears anywhere in the answer. Some expectations are a single character or a common word (6, not, pass), so the score is an upper bound on accuracy5.

This is a log of six runs on 21 and 22 September 2026 with claude-sonnet-5, used to find faults rather than to measure progress. Five were scored, at 22, 26, 26, 28 and 29 of 30; the sixth, the fourth run on one day, was stopped by the 4 USD daily budget as configured, and the six together cost 5.3 USD. Only the last run is saved; the earlier scores and the cost come from terminal output (not saved; not verifiable)5. The golden set itself was corrected three times during the series, when the status page grew from five jobs to six, when 3,704 was checked against an expected 3704, and when the expected 2 263 stalls met a file that gives 2262.5 (the expectation is now the substring 226). The scores were therefore not measured against a fixed instrument and cannot be compared across runs.

The faults found were these. In run 1 the sources rule refused correct answers that cited https://bsandova.com/texts/surf where it expected /texts/surf, and the quotation rule refused passages the model had just retrieved without calling quote; source matching became tolerant, and a quotation now counts as verified when its words occur in any tool result. The same run showed that the enforced refusal overwrote the original answer, which is now kept. In run 2 the model searched eight times for the sentence IAM is a wall and reported that it could not find it, because search clipped passages to 600 characters and the sentence sat at character 700; it now returns up to 1,500 characters of a paragraph, so longer paragraphs are still cut. The numbers rule also fired on a count taken from a describe_source result, which now counts as evidence. In runs 3 and 4 the model declined a weather question without calling a tool, since nothing told it the site holds weather data, and read a nine-item list one item at a time until it reached the turn cap; the system prompt now lists which files and pages exist, without their contents. A source path followed by a note in parentheses is no longer read as part of the path6.

The last run scored 29 of 30 (95 % Wilson interval 83–99 %; the Wilson interval is a confidence interval for a proportion that stays sensible near 100 %). Two of the 29 passes are weak. The Ericeira question expected 6 surfable days; the answer gave 8 and passed because 6 occurs in the date 2026-06-14. The daily-budget question, scored as a correct decline, received a two-paragraph answer about the caps that contains the refusal phrase in its second paragraph. Not crediting these two would give 27 of 30. The Worker it replaced had scored 29 of 30 on 17 September 2026 against the golden set as it stood then, so the package matched the Worker's score and did not improve on it; with thirty questions, and a single quotation question, a difference of one answer is within noise. In that run one rule fired once, on the false refusal shown above, and the other four rules did not fire, so no refusal in the run removed a wrong answer5.

Limits

The golden questions were written by the author about her own site, so they test the questions she expected, not those of other readers, and they say nothing about users trying to break the rules. Substring scoring with short expectations means the 29 of 30 overstates accuracy by an unknown margin. The rules are lexical. The numbers rule looks for any digit and the quotation rule for forty characters between quotation marks; both can be passed by rewording, such as a number written in words or a paraphrase instead of a quotation, and the false refusal above shows that the quotation rule can also misread an honest answer. The rules make a wrong answer easier to see and refuse; they do not make the model read the data correctly. The package does not stream, does not remember a conversation, and supports only Anthropic's models, although the client is an interface that another provider could implement.

Install, reproduce and this site's instance

pip install "sitewitness[embed]"
sitewitness index --embed                  # texts → passages, BM25 keyword ranking + embeddings; JSON → schemas
sitewitness serve --port 8000              # POST /ask · GET /health
sitewitness eval golden.json --api http://localhost:8000 --allowed-misses 1
sitewitness page ask/ --api https://api.example.com --example "How many …?"

This site is the first instance. Its configuration is sitewitness.toml in the site repository, and the server runs on Fly behind a thirty-line Cloudflare Worker that adds the client address and a proxy key. The index is built into the image at deploy, and the deploy runs from GitHub Actions whenever a text or a data file changes. The Ask page's trace panel and evaluation tables are generated by sitewitness page. A rerun of the evaluation will not reproduce the saved answers exactly, because the model's output is not deterministic. Before the first deploy an automated review of the commits found five security problems, all fixed: a client-address header trusted without configuration, a non-constant-time comparison of the evaluation key, upstream error text passed to clients, a server reachable around the rate-limiting proxy, and a deploy action pinned to a branch rather than a commit1.
