AI engineering · a tool · 21–22 September 2026 · pip install sitewitness

An agent that shows its work.

The Ask page started as two hundred lines in a Cloudflare Worker with four rules in a prompt. It ended as a package, with the rules moved out of the prompt into code, where they can be tested, and the whole thing was evaluated six times in two days. This page describes the package and what the evaluations taught, including two faults in the first version that could not have been seen without a golden set.

Overwhelmed? Here's the short version
  • sitewitness is a Python package behind the Ask page. Five rules (tool use, numbers, code, quotations, sources) are enforced in code, and an answer that breaks one is replaced by a decline, with the rule named in the trace.
  • On the thirty-question golden set where the old Worker scored 29 of 30, the package's first run scored 22. Six runs in two days brought it to 29/30; each miss was read from the trace, and some were the evaluator's own stale expectations.
  • The runs found faults in the first version: rules that refused correct answers, and a search that clipped passages to 600 characters when the sentence sat at character 700. The six runs cost 5.3 USD, and the 4 USD daily budget cut off the fourth run of the day as configured.
  • An automated review found five security problems, including a spoofable client-address header. All were fixed before the first deploy, and none was in the model itself.
  • The package does not stream, remember a conversation or use a model other than Anthropic's. It does not make the model right; it makes the model's wrongness visible and refusable.

1 · Five rules moved from the prompt into code

The first Ask asked the model nicely to take every number from a tool, to verify every quotation and to decline when the site has no data, and the Worker checked two of those things after the fact. In the package the checks are the design, as five rules, each a function over the answer and its trace. An answer with no tool call is refused, and so is a digit in the answer when the conversation holds no read_data, search or describe_source result. Fenced code, def or an HTML tag is refused. A quotation of forty characters or more is refused when the quote tool did not return it as found and it does not occur verbatim in a tool result, and a Sources: line naming a file or page the site does not have is refused as well. The first violated rule wins, the answer is replaced by the decline sentence, and the trace names the rule. A decline is never enforced against, and the rules can be switched only in the config file, never by anything the model or a user says1.

The package also has what any agent needs and most demos skip: a budget per day and a rate per address in a pluggable store, caps on tool calls, output tokens and wall time, a final turn with no tools when the cap is reached so the answer is never empty, cost computed from configured prices and labelled as such, and a trace with every tool call, its input, its size and its time. It uses no framework; the loop is eighty lines over an interface with two methods, which is also why the tests never touch the network1.

2 · What the golden set found, run by run

The golden set is thirty questions with known answers, the same set on which the Worker had scored 29 of 30. With the same model, the same questions and the same site, the package's first run scored 22, which showed that a rewrite that looks equivalent is not necessarily equivalent, and that only a fixed test can tell. Each run's misses were read from the trace, and each fix was a commit2.

Run 1 scored 22/30. Two of its misses were stale expectations, since the status page had grown from five jobs to six and a number formatted 3,704 was checked against an expected 3704; both were the evaluator's fault and were fixed as such. The other misses were real. The sources rule refused correct answers because the model wrote https://bsandova.com/texts/surf where the check wanted /texts/surf, so the rule was right and its matching was pedantic. The quotation rule refused correct answers because the model quoted a passage it had just retrieved without calling quote; the evidence was in the conversation and the rule ignored it. The fixes were tolerant source matching and counting a quotation as verified when its words occur in any tool result of the conversation, punctuation aside. The same run showed that the enforced answer replaced the original, so the trace lost what the model had said. The original is kept now, which is how every later run could be read2.

Run 2 scored 26/30, and the quotation question failed in a new way. The model searched eight times for IAM is a wall, retrieval returned the right paragraph first every time, and the model still said it could not find the sentence, because search clipped passages to 600 characters and the sentence sat at character 700. A passage is now a paragraph, returned whole. The number-without-tool rule fired on "the status page tracks 6 jobs", which had been answered from a describe_source result ("array": 6). A schema is evidence too, so such a result now counts2.

Runs 3 and 4 scored 26 and 28. In them the model declined a weather question without calling a tool, because nothing told it the site has weather data, and it read a nine-item list one item at a time until it hit the tool cap. The system prompt now lists which data files and pages exist, one line each and never their contents, and the read_data description says what find is for. The sources rule still refused surf/data.json (climatology.ericeira), a correct path with a helpful note in parentheses, so parenthetical notes are no longer treated as part of a path. In run 5, at 29/30, one rule fired: the model quoted a long note from a data file verbatim, which is what the rule is for, and the golden set expected 2 263 where the file says 2262.5, which is again the evaluator's fault2.

The six runs cost 5.3 USD and used up one day's budget, which also showed that the budget works: the fourth run of the day was cut off at the configured 4 USD with the message it was supposed to show. The weekly evaluation now runs on Monday morning on a clean budget2.

3 · Five security findings before the first deploy

An automated review read each commit as it was pushed and found five things, all real and all cheap. The client-address header (X-Forwarded-For) was trusted unconditionally, so anyone could spoof their way past the per-address limit, and a header is now trusted only when the config names it and only if its value parses as an address. The eval key, compared with ==, is now compared in constant time. Upstream error text that went to the client now goes to the log. A server on a public host could be reached around the proxy that adds the limits, so the server can now require a proxy key and answers 403 without it, which makes the Fly hostname useless on its own. A deploy action was pinned to @master and is now pinned to a commit. None of the five was in the model itself1.

4 · Running it, and this site's instance

pip install "sitewitness[embed]"
sitewitness index --embed                  # texts → passages, BM25 + embeddings; JSON → schemas
sitewitness serve --port 8000              # POST /ask · GET /health
sitewitness eval golden.json --api http://localhost:8000 --allowed-misses 1
sitewitness page ask/ --api https://api.example.com --example "How many …?"

This site is the first instance: the config is sitewitness.toml in the repository, the server runs on Fly behind a twenty-line Cloudflare Worker that adds the client address and the proxy key, the index is built in the image at deploy, and the deploy runs from GitHub Actions whenever a text or a data file changes. The Ask page's trace panel and evaluation tables come from sitewitness page with the site's own stylesheet1.

The package does not stream, remember a conversation or use a model other than Anthropic's, though the client is an interface with two methods. Nor does it make the model right; it makes the model's wrongness visible and refusable, which on the evidence of the detector text is the most a run-time system can do.
