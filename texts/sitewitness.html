AI engineering · a tool · 21–22 September 2026 · pip install sitewitness

An agent that shows its work.

The Ask page started as two hundred lines in a Cloudflare Worker with four rules in a prompt. It ended as a package: the rules moved out of the prompt into code, where they can be tested, and the whole thing was evaluated six times in two days. This is what the package is, and what the evaluations taught, including the two things that were wrong with the first version and could not have been seen without a golden set.

1 · From a prompt to a protocol

The first Ask asked the model nicely: every number from a tool, every quotation verified, decline when the site has no data. It also checked two of those things after the fact, in the Worker. The package makes the check the design. Five rules, each a function over the answer and its trace: an answer with no tool call is refused; a digit in the answer with no read_data, search or describe_source result in the conversation is refused; fenced code, def or an HTML tag is refused; a quotation of forty characters or more that neither the quote tool returned as found nor occurs verbatim in a tool result is refused; a Sources: line naming a file or page the site does not have is refused. The first violated rule wins, the answer is replaced by the decline sentence, and the trace names the rule. A decline is never enforced against. The rules can be switched only in the config file, never by anything the model or a user says1.

The rest is what any agent needs and most demos skip: a budget per day and a rate per address in a pluggable store, caps on tool calls, output tokens and wall time, a final turn with no tools when the cap is reached so the answer is never empty, cost computed from configured prices and labelled as such, and a trace with every tool call, its input, its size and its time. No framework: the loop is eighty lines over an interface with two methods, which is also why the tests never touch the network1.

2 · What the golden set found, run by run

Thirty questions with known answers, the same set the Worker had scored 29 of 30 on. The package's first run scored 22. Same model, same questions, same site. The golden set was doing its job: a rewrite that looks equivalent is not, and only a fixed test can say so. Each run's misses were read from the trace, and each fix was a commit2.

Run 1, 22/30. Two stale expectations (the status page had grown from five jobs to six; a number formatted 3,704 against an expected 3704), which are the evaluator's fault and were fixed as such. Then the real ones. The sources rule refused correct answers because the model wrote https://bsandova.com/texts/surf and the check wanted /texts/surf: the rule was right, the matching was pedantic. The quotation rule refused correct answers because the model quoted a passage it had just retrieved, without calling quote: the evidence was in the conversation, and the rule ignored it. Fix: tolerant source matching; a quotation counts as verified when its words occur in any tool result of the conversation, punctuation aside. Also from this run: the enforced answer replaced the original, so the trace lost what the model had said. The original is kept now, which is how every later run could be read2.

Run 2, 26/30. The quotation question failed in a new way: the model searched eight times for IAM is a wall, retrieval returned the right paragraph first every time, and the model still said it could not find the sentence. search clipped passages to 600 characters and the sentence sat at character 700. Fix: a passage is a paragraph; return it whole. The number-without-tool rule fired on "the status page tracks 6 jobs", answered from a describe_source result ("array": 6): a schema is evidence too. Fix: count it2.

Runs 3 and 4, 26 and 28. The model declined a weather question without calling a tool, because nothing told it the site has weather data; and it read a nine-item list one item at a time, hitting the tool cap. Fix: the system prompt now lists what data files and pages exist, one line each, never their contents; and the read_data description says what find is for. The sources rule still refused surf/data.json (climatology.ericeira), a correct path with a helpful note in parentheses. Fix: parenthetical notes are not part of a path. Run 5, 29/30, one rule fired: the model quoted a long note from a data file verbatim, which is what the rule is for, and the golden set expected 2 263 where the file says 2262.5, which is the evaluator's fault again2.

Six runs cost 5.3 USD and used up one day's budget, which is a finding in itself: the budget worked, the fourth run of the day was cut off at the configured 4 USD with the message it was supposed to show. The weekly evaluation now runs on Monday morning on a clean budget2.

3 · Five security findings before the first deploy

An automated review read each commit as it was pushed and found five things, all real and all cheap. The client-address header (X-Forwarded-For) was trusted unconditionally, so anyone could spoof their way past the per-address limit; now a header is trusted only when the config names it, and only if its value parses as an address. The eval key was compared with ==; now with a constant-time comparison. Upstream error text went to the client; now it goes to the log. A server on a public host could be reached around the proxy that adds the limits; now the server can require a proxy key and answers 403 without it, so the Fly hostname is useless on its own. And a deploy action was pinned to @master; now to a commit. The general lesson is not new, but it was confirmed again: the interesting bugs in an agent are not in the model1.

4 · Running it

pip install "sitewitness[embed]"
sitewitness index --embed                  # texts → passages, BM25 + embeddings; JSON → schemas
sitewitness serve --port 8000              # POST /ask · GET /health
sitewitness eval golden.json --api http://localhost:8000 --allowed-misses 1
sitewitness page ask/ --api https://api.example.com --example "How many …?"

This site is the first instance: the config is sitewitness.toml in the repository, the server runs on Fly behind a twenty-line Cloudflare Worker that adds the client address and the proxy key, the index is built in the image at deploy, and the deploy runs from GitHub Actions whenever a text or a data file changes. The Ask page's trace panel and evaluation tables come from sitewitness page with the site's own stylesheet1.

What it does not do: stream, remember a conversation, or use a model other than Anthropic's, though the client is an interface with two methods. And it does not make the model right. It makes the model's wrongness visible and refusable, which on the evidence of the detector text is the most a run-time system can do.
