What it does, and comparable tools

The Ask page answers questions about this site from its texts and data files. It started as about two hundred lines in a Cloudflare Worker, with four rules written into the prompt, two of them checked after the fact. sitewitness is the Python package that replaced it on 21 and 22 September 2026. It indexes a site's texts into passages and its JSON files into schemas, gives a model five tools (search, read_data, describe_source, quote and list_sources, which lists the site's data files), runs the agent loop (the model calling tools turn by turn until it answers) behind a small server, and applies five rules to every answer before it is returned. An answer that breaks a rule is replaced by a fixed refusal, and the trace, the per-answer log of tool calls, tokens and rule results, records which rule fired1.

Output checks of this kind are common. Guardrails AI wraps model calls in input and output guards built from validators, many of them published on its hub2. NeMo Guardrails defines input, dialog, retrieval, execution and output rails, several of which are themselves model calls, such as self-checking for hallucination3. RAGAS measures faithfulness offline by having a model split an answer into claims and checking each claim against the retrieved context4. sitewitness is cruder. Its rules are plain functions over the answer text and the trace of tool calls, with no second model, so they are deterministic, cheap and testable, and they check only what can be read off the text, such as whether a number appears when no data were read.

Method: five rules and the run-time limits

An answer with no tool call is refused, as is one containing a digit when the conversation holds no result from read_data, search or describe_source. Fenced code, a line starting with def, import or from, or an HTML tag is refused. A passage of forty characters or more inside quotation marks is refused unless its words occur in a tool result of the conversation or the quote tool returned any phrase as found in that conversation; one verified quotation therefore exempts every other quotation in the same answer. A Sources: line naming a file or page the site does not have is refused too. The first violated rule wins, and the original answer is kept in the trace. A refusal is never itself refused, and the rules can be switched off only in the configuration file1.

Around the rules sit the limits a public endpoint needs: a daily budget and a per-address rate in a pluggable store, caps on tool calls (max_tool_calls = 8 on this site), output tokens and wall time, and a final turn without tools when a cap is reached, so that an answer is never empty. The tool-call cap is checked before each model turn, not after each call, so all the calls of the turn that crosses it are run, and saved answers used up to 17. Cost is computed from configured prices, and the trace records every tool call with its input, size and time. The package uses no agent framework; the model client is an interface with one method1.

Worked example: one traced answer

The saved evaluation of 22 September 2026 (ask/eval-2026-09-22.json, committed in f91a0b1) contains one answer that a rule replaced; its record, shortened, follows5.

q         Which September watch runs have an unverified model attribution?
expect    unverified
tools     describe_source, read_data × 8
original  Only one September run has an unverified model attribution: the "opus" alias run on the
          abstention pack dated 2026-09-14 (…). Its model field is recorded as "unverified" because …
enforced  quotes_need_verification
answer    I can't answer that from this site. This assistant answers only from the site's data files …
ok        false

The original answer contains the expected word. In this one trace the quotation rule fired because its pattern takes any forty or more characters between two quotation marks as a quotation, here the text between two short quoted words, "opus" and "unverified", marked above. The refusal was therefore a false one, and the run's only miss; the diagnosis rests on this single record, not on a repeated test.

Tests and the evaluation runs

The package's 47 tests run on Python 3.10 to 3.13 in GitHub Actions and passed locally on 29 September 2026; the model client is replaced by a stub, so no test calls the network. The golden set is thirty questions about the site, each with an expected substring or refusal. 18 are labelled as data questions whose answer must come from read_data (13 expect a number, 5 a name or status read from a file), 7 as text questions, 1 as a quotation and 4 should be declined. An answer counts as correct if it contains the expected string anywhere after case, spaces and thousands separators are normalised, unless it also contains the refusal phrase; a decline counts if the refusal phrase appears anywhere in the answer. Some expectations are a single character or a common word (6, not, pass), so the score is an upper bound on accuracy5.

The six runs on 21 and 22 September 2026 with claude-sonnet-5 were used to find faults rather than to measure progress. Five were scored, at 22, 26, 26, 28 and 29 of 30; the sixth, the fourth run on one day, was stopped by the 4 USD daily budget as configured, and the six together cost 5.3 USD. Only the last run is saved; the earlier scores and the cost come from terminal output (not saved; not verifiable)5. The golden set itself was corrected three times during the series (table below), so the scores were not measured against a fixed instrument and cannot be compared across runs.

The last run scored 29 of 30 (95 % Wilson interval 83–99 %; the Wilson interval is a confidence interval for a proportion that stays sensible near 100 %). Two of the 29 passes are weak. The Ericeira question expected 6 surfable days; the answer gave 8 and passed because 6 occurs in the date 2026-06-14. The daily-budget question, scored as a correct decline, received a two-paragraph answer about the caps that contains the refusal phrase in its second paragraph. Not crediting these two would give 27 of 30. The Worker it replaced had scored 29 of 30 on 17 September 2026 against the golden set as it stood then, so the package matched that score and did not improve on it. With thirty questions, and a single quotation question, a difference of one answer is within noise. In that run only the quotation rule fired, once, on the false refusal shown above, so no refusal in the run removed a wrong answer5.

Limits

The golden questions were written by the author about her own site, so they test the questions she expected, not those of other readers, and they say nothing about users trying to break the rules. Substring scoring with short expectations means the 29 of 30 overstates accuracy by an unknown margin. The rules are lexical, and both the numbers rule and the quotation rule can be passed by rewording, such as a number written in words or a paraphrase instead of a quotation, and the false refusal above shows that the quotation rule can also misread an honest answer. Whether the rules make a wrong answer easier for a reader to spot was not measured, and they do not make the model read the data correctly. The package does not stream, does not remember a conversation, and supports only Anthropic's models, though another provider could implement the client interface.

Install, reproduce and this site's instance

pip install "sitewitness[embed]"
sitewitness index --embed                  # texts → passages, BM25 keyword ranking + embeddings; JSON → schemas
sitewitness serve --port 8000              # POST /ask · GET /health
sitewitness eval golden.json --api http://localhost:8000 --allowed-misses 1
sitewitness page ask/ --api https://api.example.com --example "How many …?"

On this site, the first instance, the configuration is sitewitness.toml in the site repository and the server runs on Fly behind a thirty-line Cloudflare Worker that adds the client address and a proxy key. The index is built into the image at deploy, which runs from GitHub Actions whenever a text or data file changes. The Ask page's trace panel and evaluation tables are generated by sitewitness page. A rerun will not reproduce the saved answers exactly, because the model's output is not deterministic. Before the first deploy the author found five security problems while self-auditing the commits, all fixed and listed below1.
