Ask the site · live

Ask the site. It shows its work.

A small agent that knows this site's data and texts, and nothing else. Every number it gives you comes from a file it actually read, every quotation is checked word for word, and when the site doesn't know, it says so. Go on, try to catch it out.

    5 tools………

    It reads, it doesn't guess

    Five tools: list the data files, describe one, read a slice, search the texts, verify a quotation. A number without a file behind it is withheld.

    Quotes are checked

    Every quotation is matched word for word against the text before you see it.

    It says no

    No phone numbers, no forecasts for next Christmas, no poems: when the site has no data, it declines.

    You get the receipt

    Under each answer: which files it read, how long it took, what it cost and which rules it passed.

    How it is scored

    Thirty golden questions with known answers, run against the live API by ask/eval.py, results below as they came back. Eighteen ask for a number in a data file, seven for something said in a text, one demands a verbatim quotation, and four should be declined: a phone number, a forecast for Christmas, a poem, a question about the assistant's own configuration. A question counts as correct when the expected value is in the answer, or when the right response is a refusal and it refused. Two protocol flags are computed from the trace, not from the text: a number stated without any tool result in the conversation, and a quotation without a verified quote call1.

    Every evaluation weekly, every Monday

    The golden set runs every Monday morning against the live API and appends one row here, so a change in the model, the prompt or the data files shows up as a change in the score, not as a quiet drift. Same idea as the model release watch, pointed at this site's own agent.

    Run this on your own site pip install sitewitness

    Everything on this page is pip install sitewitness. A folder of texts and JSON files, one config file, five commands, and you have the same agent, the same five rules enforced in code, the same evaluation runner and this page. The trust protocol is the package; the site is the argument for it.

    pip install "sitewitness[embed]"
sitewitness index --embed                       # texts → passages, BM25 + embeddings; JSON → schemas
sitewitness serve --port 8000                   # POST /ask · GET /health
sitewitness eval golden.json --api http://localhost:8000
sitewitness page ask/ --api https://api.example.com --example "How many …?"
    # sitewitness.toml
[site]
name = "example.com"
texts = ["texts/**/*.html"]
[site.data]
"data/results.json" = "What the file holds, in one line the model will read."

[limits]
max_tool_calls = 8
daily_budget_usd = 4.0
per_ip_per_hour = 12

    The five rules (require_tool_use, numbers_need_tool, forbid_code, quotes_need_verification, sources_must_exist) live in protocol.py as checks over the answer and its trace; a prompt can ask for them, only the config can switch them off. 47 tests, none of them touching the network: the model client is an interface with a fake in the suite. The server behind this page runs on Fly behind a Cloudflare Worker that adds a proxy key, so it cannot be reached around the limits1.

    What it is not

    Not a search engine over the web, not a chat about anything, and not a place where a wrong number can hide: the trace under every answer says which file was read. Four guardrails are enforced in code, not in the prompt: an answer produced without any tool call, a number without a tool result, code in the answer, or a quotation that was not verified is replaced by a refusal, and the trace says so. The one miss in the table above is the theme of this site in miniature: the agent read a text instead of the data file and attributed 2 745 stalls to the wrong series, confidently. The cross-check would have caught it; the golden set did. The model is the configured one in the trace, and the cost shown is computed from configured list prices, not from a bill. If today's budget is spent, it says so and the data files stay readable by hand. The agent is the package above; the Worker at api.bsandova.com is a twenty-line proxy1.
