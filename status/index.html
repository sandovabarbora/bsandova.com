Status · what runs this site · read live from the data files and the public GitHub API

Five jobs, no server.

Every live thing on this site is a scheduled job writing a data file that a static page reads. This page reads the same files and asks GitHub what ran, then judges freshness against the cadence each job promised. A card goes green only when a source said so; when a source cannot be read, the card says that, because a status page that guesses is worse than none.

How a card is judged

statemeaning
freshthe newest data (or deploy) is younger than the job's cadence, and the last run, where a run log exists, succeeded
lateolder than one cadence but younger than two: one missed run
staleolder than two cadences, or the last run failed
unknowna source could not be read (the GitHub API allows 60 unauthenticated requests an hour per address); nothing is assumed

Cadence is declared per job in jobs.json, next to the schedule, the sources and the links. The page has no memory: it does not store history, does not notify anyone, and shows the last run only. History lives in the data files and in the GitHub run logs the cards link to. Nothing here is typed.
