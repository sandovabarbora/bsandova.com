Silently wrong, ecommerce pack

Twenty-six questions, each built around one way a number comes back wrong and looks fine, three repeats each, Czech. A silent failure is an answer that runs, returns a plausible number, and is wrong. Lower is better; a refusal is not a silent failure.

Declined, abstention pack

Ten questions that reach past the edge of the data: every column exists, only the data is missing, and every query runs and returns a number. Declining is the correct answer to all ten. Higher is better.

Every run

The alias is what an operator types; the model column is what actually answered, as the tool reported it. A dagger (†) marks a run whose model attribution is unverified: the note in data.json says why, and the run is not counted as evidence about a named model until it is re-run. Fingerprints are SHA-256 prefixes of the question set, the warehouse and the system prompt, so a change in any input shows up as a change in the row, not as a quiet shift in the line above.

How it runs

On the first of the month a job on my machine runs the Quaesitor harness with the operator's own Claude Code hooks stripped (they inject context no customer would have), for each model alias and each pack, then indexes the reports and pushes this page's data file. Nothing on the page is typed; if a run fails there is a gap, not a guess. The harness, the packs and the classification rules are the ones behind the Quaesitor texts; the method is described there.

Budget: roughly six dollars for an opus sweep of the ecommerce pack, four for sonnet, two for haiku; about half that for the abstention pack. The cost of every run is in the table.

Data. data.json, one record per run: date, alias, actual model, tool version, pack, outcomes, unstable questions, cost, fingerprints, archived report. Produced by src/watch_index.py in the harness repository from the reports the harness writes.
